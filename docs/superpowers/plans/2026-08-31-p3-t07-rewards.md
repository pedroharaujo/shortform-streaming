# P3-T07 rewarded-ad implementation plan

> **For agentic workers:** Use superpowers:subagent-driven-development. The user
> authorized continuous implementation and a focused, unmerged PR.

**Goal:** Server-bound rewarded intents, authentic SSV, one permanent episode
entitlement and a consent-gated Android test-ad flow.

**Architecture:** Django advertising module reuses catalog eligibility,
entitlements and account identity locks. Android uses generated OpenAPI types
and a small test-only rewarded adapter. The client never grants access.

**Tech Stack:** Django/DRF, PostgreSQL, Python cryptography, Expo/React Native,
react-native-google-mobile-ads, Jest and pytest.

## Global constraints

- One task P3-T07 per PR, branch from main in this checkout; no extra worktrees.
- Never merge automatically. Unavailable required checks are blockers.
- Android / Google Play only (D-027); no consumer web or iOS implementation.
- One verified ad permanently unlocks one episode (D-007), login first (D-005).
- No live ads, production tracking, paid services, licensed media or secret data.
- Preserve consent, eligibility, playback and account-deletion guards.
- Use expand-only migrations and update OpenAPI with the generated client.
- Do not edit private .env files; use EXPO_NO_DOTENV=1 for deterministic checks.
- Do not run Metro's watcher concurrently with repository temporary-dir tests.
