# Development privacy notice design

**Task:** P3-T07-F1 / #96. The founder asked the agents, using Superpowers,
startup-cto and solo-founder, to choose the setup and prepare the missing notice.
This delegates drafting and reversible development choices, not fabrication of
the operator's identity or approval of public production processing.

## Decision

Prepare one English notice for founder-controlled Android emulator validation,
using synthetic email/password accounts and generated media. No public testers,
real Google Sign-In, paid ads, production rewards or consumer website are added.
Explain local account/progress/reward state separately from real provider
network processing. Keep D-020 and D-025 production decisions unchanged.

Keep the notice in the existing public repository. First assess a rendered,
versioned document URL when the notice is complete; it adds no infrastructure.
Google does not explicitly certify GitHub-rendered Markdown as an approved
format. Before use, verify the exact logged-out/mobile page, readability and
Google's policy-page script restrictions. If unsuitable, use a separate plain
static document host; do not repurpose the callback tunnel to serve documents.
A raw Markdown response has poorer readability and is not the default.

Use an app-specific European regulations message: English, EEA/UK/Switzerland,
first-screen Do not consent wherever the message appears, close-as-refusal off.
Keep account-wide vendor/purpose settings unchanged. The displayed partner list
must be checked; no mediation configuration is not proof of Google-only receipt.

## Boundaries and validation

The draft is not an active policy or legal certification. Operator name and
monitored contact must be supplied for public use. Effective date is set when
activated. Describe current deletion limits and provider uncertainty explicitly;
do not promise immediate universal erasure, zero collection or EU-only residency.

Choose a manual development-data closeout rule, limited to the dedicated test
environment; clearly distinguish it from implemented automatic deletion. Verify
provider metadata settings each session. No existing database is deleted here.

Independent agents check technical facts and the scope against current primary
Google/CNIL guidance. A separate reviewer checks the resulting draft/checklist.
Run repository safety/governance tests and whitespace checks. No app behavior or
API contract changes require duplicate runtime tests. Publication/configuration
and the native ad/SSV/playback journey remain separate incomplete steps.
